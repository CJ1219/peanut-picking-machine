## 2026-09-05：GoPro 生產整合版更新

本節為新版差異；下方原有章節保留作為影片測試版操作說明。原有工單、SQLite、Qwen、影片七幀判定、模型更新及回復流程保留。

### 啟動與選擇來源

```powershell
python -m pip install -r requirements-gopro.txt
python run_gui.py
```

1. 建立或確認工單。
2. 上方來源選擇「影片測試」或「GoPro 生產（控制 Arduino）」。預設為 GoPro 即時生產。
3. GoPro 模式填入 Arduino COM（預設 `COM7`）及 GoPro 序號尾碼（預設 `468`），按「開始生產」。這會連線、初始化四個撥桿至 135°，並在模型、GoPro 和第一張畫面都準備完成後送出 `L` 啟動輸送，不需另開 detect_open_gopro.py。
4. 即時影像在 GUI 顯示；最終分類在到達觸發線後寫入工單，更新數量、比例及已校正的重量。
5. 「暫停」送出 `S` 並暫停辨識；「繼續」送出 `L` 並恢復辨識；「停止生產」立即送出 `S`，接著結束辨識、將撥桿回到 135°並釋放 GoPro／序列埠。關閉視窗也會走相同停止流程。

Arduino 韌體使用 `L` 啟動輸送、`S` 停止輸送。錯誤、目標重量達標與程式結束時也會嘗試送出 `S`。這是軟體控制，仍不能取代實體緊急停止開關。

實體綠色按鈕啟動後，Arduino 會回報 Python 並讓 GUI 顯示運轉；實體紅色按鈕停止後，GUI 會同步顯示停止。黃色按鈕要求 Python 重新檢查全部未清除異常：執行期錯誤等已不再成立的異常會清除；未填生產設定或目標重量仍已達標等可當場確認的異常會保留。燈號為運轉綠燈長亮、停止紅燈長亮、異常黃燈閃爍。必須將新版 `中興AI競賽/arduio/main_control/main_control.ino` 重新燒錄到 Arduino，實體按鈕回報及燈號才會生效。

選擇開關用於方向：LOW 側為 `L`，HIGH 側為 `R`。綠色按鈕與 Python 的「開始／繼續」都依選擇開關目前方向啟動。運轉中切換方向時，Arduino 會先停止 100 ms 再反向，並把新方向回報 GUI。如果機台實際面板的左右標示相反，可交換程式中的 LOW／HIGH 對應。

### GoPro 使用完成版規則

- 保留 detect_open_gopro.py 的透視四點、1920×1080 校正、銳化、1024 推論、0.5 信心及專用 ByteTrack 設定。
- small 任一幀出現即永久鎖定；mold 使用最近 10 幀至少 5 次；判定線 X=400，觸發線 bbox 左側 X≤5。
- 沿用完成版更新的透視點 (550,40)、(1645,99)、(1918,992)、(342,1034)，依串流實際解析度縮放；四道 Y 區域為 75–330、300–568、538–781、751–923。保留重疊雙道排除；短暫遺失預測沿用原程式第一個匹配道的控制方式。
- 現場 normal 不送伺服角度指令，NG 送 45°。同一幀、同一通道同時有 normal 與 NG 時，以 NG 為準並送 45°，生產統計只計 NG；normal 不會再送 135°覆蓋排除動作。
- 逐顆紀錄使用實際觸發時的分類，狀態為 `GOPRO_TRIGGERED` 或 `GOPRO_PREDICTED`；同一追蹤 ID 每次執行只計一次。
- 裁切與完整無框圖保存判定線附近影像；平均信心和面積使用觸發前最多 10 次觀測，並非影片版七幀。GoPro 樣本先進人工標註分流。
- 尚未到觸發線就停止或消失的花生不計入完成數量。GoPro 模式尚未推估 normal 誤排率；畫面原有誤排統計只反映影片模式已記錄的估計值。
- GoPro 面積使用校正後解析度，原先影片重量係數不能直接假定適用，需另行實測。

### 模型、移機與依賴

- GoPro 生產以 `中興AI競賽/detect_open_gopro.py` 為共用引擎，使用該完成版的 train-13 模型；GUI 不再以影片資料庫的啟用模型覆蓋它。影片模式仍保留模型更新／回復行為。
- 優先使用完成版指定的 `D:/中興AI競賽/runs/detect/train-13/weights/best.pt`；該檔不存在時使用專案內同一相對路徑，紀錄版本 `gopro-train-13` 與實際雜湊。
- 移機必須附帶上述完成版權重，以及 `中興AI競賽/peanut_bytetrack.yaml`；不要只複製 peanut_app。
- GoPro 額外需要 `pyserial`、`multi-webcam==0.2.0`；本機可找到這些套件。原有資料庫絕對路徑的移機限制仍存在。
- 連線、串流中斷、傳送或資源清理錯誤會進入 GUI 異常流程。自動測試使用模擬硬體，不代表已完成實機驗收。

### GoPro 即時畫質

GoPro Webcam 串流最高可指定 1080p。`multi_webcam` 的啟動呼叫可寫成：

```python
gopro.start(port=GOPRO_PORT, resolution=12, fov=0)
```

其中 `resolution=12` 是 1080p，`fov=0` 是 Wide；其他鏡頭值為 Linear `4`、Narrow `2`、SuperView `3`。解析度與 FOV 必須一起指定。改變 FOV 後，現有透視校正四點與四道 Y 範圍可能不再準確，必須重新拍攝並校正。

目前程式的 `OUTPUT_WIDTH=1920`、`OUTPUT_HEIGHT=1080` 只是透視輸出尺寸；若 GoPro 原始串流較低，放大到 1920×1080 不會增加真實細節。YOLO 的 `imgsz=1024` 可再提高，例如 1280，但會增加 GPU 負擔及延遲。現場通常應先改善照明、縮短拍攝距離並固定曝光，再提高推論尺寸。

## 1. 移機前必看

只傳送 `code` 資料夾，**不一定能直接辨識**。目前程式還需要兩個 YOLO 權重檔，而且預設會在 `code` 的上一層尋找 `yolo` 資料夾。

接收者至少要拿到：

- 完整的 `code` 資料夾。
- `yolov26s_best.pt`：線上辨識使用的 s 模型，約 20 MB。
- `中興AI競賽/runs/detect/train-13/weights/best.pt`：AI 更新時使用的 x 花生三分類模型。
- 至少一支可供測試的影片；不一定要使用原本的 `video_001.mp4`。
- 若要使用本地 Qwen 分析，接收者的電腦必須另外安裝 Ollama 及 `qwen3.5:9b`。Ollama 模型不包含在 `code` 資料夾內。
- 若要保留原電腦的生產紀錄、花生圖片、訓練資料及重量校正，必須完整保留 `code/production_data`。

建議交付的資料夾結構：

```text
花生機/
├─ code/
│  ├─ run_gui.py
│  ├─ requirements.txt
│  ├─ peanut_app/
│  ├─ tests/
│  └─ production_data/       ← 要保留歷史資料時才一起交付
├─ yolo/
│  ├─ yolov26s_best.pt       ← 必要
│  └─ yolov26x_best.pt       ← 使用 AI 更新時必要
└─ 影片素材/
   └─ video_001.mp4          ← 可選，也可從 GUI 選擇其他影片
```

如果堅持只傳一個 `code` 資料夾，仍要把 `yolo` 模型檔另外交給對方，並請對方在 `code` 的上一層建立 `yolo` 資料夾後放入模型。模型放在 `code/yolo` 內目前不會被程式自動找到。

### 舊資料庫移機注意事項

`production_data/peanut_production.sqlite3` 會保存部分舊電腦的絕對路徑，包括模型權重、花生圖片及訓練樣本位置。因此：

- 舊工單、數量、信心值、異常與統計仍保存在資料庫中。
- 移到不同使用者名稱或不同磁碟位置後，舊圖片路徑、舊模型回復及沿用舊樣本訓練可能找不到檔案。
- 目前程式**還沒有自動移機修復路徑功能**。

交付前請選擇其中一種方式：

1. **全新使用，最穩定：**保留原始資料備份，只在「準備寄出的副本」中移除 `production_data`。第一次啟動會建立新的資料庫與資料夾。
2. **保留歷史資料：**完整交付 `production_data`，但正式使用「模型回復」或「舊樣本再訓練」前，需先進行資料庫路徑移機。不要為了測試而刪除唯一一份原始資料。

複製或備份前，先停止辨識並關閉 GUI，以免 SQLite 或圖片仍在寫入。

## 2. 目前版本的功能範圍

目前已可使用：

- Windows Tkinter GUI。
- 960 × 540 比例的辨識畫面。
- 影片檔辨識，花生移動方向為由右往左。
- 工單建立、物料批號手動輸入與攝影機掃碼。
- normal、mold、small、unknown 數量及百分比。
- 中央前 3 幀、中央幀、中央後 3 幀的七幀判定。
- 每顆花生裁切圖、完整無框線原始幀及當時全部花生座標保存。
- 四道與三個道間邊界判定、預估 normal 誤排除率。
- SQLite 生產紀錄、異常紀錄、訓練樣本及模型版本紀錄。
- 本機 Ollama `qwen3.5:9b` 生產數據分析。
- x 模型自動標註、人工確認分流、s 模型訓練、啟用與回復。

目前尚未完成或仍為暫定：

- **辨識來源目前是影片檔，不是即時 GoPro 畫面。**GoPro／攝影機目前只用於掃描物料批號。
- **Python 尚未連接 Arduino，也不會送出步進馬達或伺服指令。**目前只計算預定撥片道別與中央通過後 1 秒的指令時間。
- 重量公式尚未實測校正，預設停用，因此不會用虛構重量觸發目標重量停止。
- mold／small 七幀門檻、道間邊界寬度、撥片時機及誤排判斷仍需使用實際設備校正。
- 新模型訓練完成後會自動啟用，但目前沒有設定「新模型至少必須優於舊模型才可啟用」的驗收門檻。

## 3. 新電腦需求

### 必要項目

- Windows 10 或 Windows 11，64 位元。
- Python 3.11，64 位元。本專案目前在 Python 3.11.9 測試通過。
- 足夠的磁碟空間；訓練資料、逐顆圖片與模型訓練結果會持續增加。
- `yolov26s_best.pt` 模型。
- 測試影片。

### 建議硬體

- NVIDIA GPU：辨識與訓練速度會明顯較好。
- 沒有相容 GPU 時仍可嘗試用 CPU，但辨識、x 模型自動標註與訓練可能很慢。
- 使用 `qwen3.5:9b` 時，建議預留至少 10 GB 可用磁碟空間給 Ollama 與模型；目前測試電腦上的模型約 6.6 GB，執行時還需要額外記憶體。

### 選用項目

- Ollama 與 `qwen3.5:9b`：只有「Qwen 分析」需要；其他統計與 YOLO 辨識不依賴 Qwen。
- GoPro 或一般攝影機：只有物料批號掃碼需要。
- `yolov26x_best.pt`：只有「AI 更新／離線自動標註」需要。

## 4. 第一次安裝

### 4.1 安裝 Python

從 Python 官方網站安裝 Python 3.11 的 64 位元版本：

- <https://www.python.org/downloads/release/python-3119/>

安裝時建議勾選 `Add Python to PATH`。安裝完成後開啟 PowerShell：

```powershell
python --version
```

應顯示 `Python 3.11.x`。如果 `python` 指令無法使用，可改試：

```powershell
py -3.11 --version
```

### 4.2 建立獨立 Python 環境

在檔案總管進入 `code`，點一下上方路徑列，輸入 `powershell` 後按 Enter。接著執行：

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r .\requirements.txt
```

這會安裝：

- NumPy
- OpenCV contrib
- Pillow
- Ultralytics YOLO
- Ultralytics 所需的 PyTorch 等相依套件

若要確認 NVIDIA GPU 是否被 PyTorch 使用：

```powershell
.\.venv\Scripts\python.exe -c "import torch; print('CUDA:', torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else '目前使用 CPU')"
```

若顯示 `CUDA: False`，程式仍可能以 CPU 執行。若需要 GPU 版 PyTorch，請依新電腦的顯示卡與驅動版本，使用 PyTorch 官方安裝選擇器產生安裝指令：

- <https://pytorch.org/get-started/locally/>

### 4.3 準備 YOLO 模型

確認以下檔案存在，而且名稱完全相同：

```text
花生機/yolo/yolov26s_best.pt
花生機/yolo/yolov26x_best.pt
```

其中：

- s 模型是開始辨識的必要檔案。
- x 模型不是一般辨識的必要檔案，但進行 AI 更新時一定需要。

### 4.4 準備影片

預設影片位置是：

```text
花生機/影片素材/video_001.mp4
```

如果沒有這支影片，可在 GUI 上方按「選擇影片」，選擇其他 `.mp4`、`.avi`、`.mov` 或 `.mkv` 檔。

影片內容目前必須符合：

- 花生由畫面右側往左側移動。
- 花生會通過畫面水平中央線。
- 相機角度及四道位置盡量與模型訓練資料一致。

### 4.5 安裝本機 Qwen（選用）

若要使用「Qwen 分析」，從 Ollama 官方網站安裝 Windows 版：

- <https://ollama.com/download/windows>

安裝後在 PowerShell 執行：

```powershell
ollama run qwen3.5:9b
```

第一次執行會下載模型。看到 `>>>` 後代表可以使用，可輸入 `/bye` 離開對話；Ollama Windows 版通常會繼續在背景提供本機服務。

檢查模型：

```powershell
ollama list
```

清單中必須看到 `qwen3.5:9b`。

本程式只會連線：

```text
http://127.0.0.1:11434/api/generate
```

不使用區網，也不會把提示內容或生產資料送到另一台電腦。網路只在安裝套件與第一次下載 Ollama 模型時需要。

## 6. 一般操作流程

### 6.1 建立生產工單

1. 啟動 GUI。
2. 按「生產設定」。
3. 填入：
   - 廠商編號：3 位數字，例如 `001`。
   - 花生種類編號：3 位數字，例如 `001`。
   - 物料批號：例如 `SUP001-20260830-A01`；格式目前不強制，可依現場規則輸入。
   - 物料製造日期：格式必須為 `YYYY-MM-DD`，例如 `2026-08-30`。
   - 生產目標重量：以 kg 輸入，必須大於 0，例如 `25`。
4. 按「建立新工單」。

物料批號也可以使用「GoPro 掃碼」：

1. 先輸入攝影機索引，通常第一台攝影機是 `0`。
2. 按「開始掃碼」。
3. 將 QR Code 或一般條碼放到畫面中央。
4. 成功後內容會自動填入物料批號。

攝影機索引 `0` 無法開啟時，可依序嘗試 `1`、`2`。使用 GoPro 前，需先讓 Windows 能把 GoPro 辨識為可用攝影機。

### 6.2 工單號規則

工單號由程式自動產生，例如：

```text
26H30-001-001-001
```

意義如下：

```text
26       西元年份後兩碼
H        月份代碼；A=1 月、B=2 月……L=12 月，因此 H=8 月
30       生產日期
001      廠商編號
001      花生種類編號
001      同日、同廠商、同種類的工單流水號
```

物料批號與工單號不同：物料批號由使用者輸入或掃碼，工單號則由程式產生。

### 6.3 開始辨識

1. 確認 GUI 上方已有目前工單。
2. 按「選擇影片」並選擇影片。
3. 按「開始」。
4. 第一次載入模型可能需要等待。
5. 影片中的花生由右往左通過中央時，程式會等待中央後 3 幀，再完成七幀判定與紀錄。

操作按鈕：

- 「開始」：開始辨識；暫停狀態下也可繼續。
- 「暫停」：暫停影片與辨識，再按一次可繼續。
- 「停止」：停止 Python 辨識；目前不會傳送 Arduino 指令。

辨識結果優先順序：

```text
mold > small > normal
```

`unknown` 不是第四種瑕疵類別，而是程式已追蹤到花生，但因有效幀不足、信心不足、遮擋、重疊、追蹤中斷，或停止時尚未收完中央後 3 幀，無法可靠判為 normal／mold／small。unknown 會保留供後續人工標註，不會自動視為 normal。

主畫面會顯示：

- normal、mold、small、unknown 數量及比例。
- 累計估算重量；未校正時顯示「待校正」。
- 預估被誤排的 normal 數量及誤排除率。
- 最近一顆花生的分類、中央信心、七幀平均信心、面積、重量、道別、邊界、撥片計畫及模型版本。

### 6.4 異常狀況

按「異常狀況」可查看及清除異常，例如：

- 尚未填入生產資料。
- 已達生產目標重量。
- 辨識執行錯誤。

嚴重異常未清除時不能重新開始。目標重量達標被視為可清除異常，但如果清除後仍使用同一張工單重新啟動，因累計重量仍已達標，設備會立刻再次停止。

## 7. AI 數據分析

1. 在主畫面按「AI 更新」。
2. 選擇「AI 數據分析」分頁。

## 8. AI 模型更新

進行訓練前：

- 先停止辨識，避免 GPU 資源衝突。
- 確認 `yolov26x_best.pt` 與目前 s 模型都存在。
- 建議接上電源，並保留足夠磁碟空間。
- 至少要有兩個不同工單／物料批次的可用資料，才能把訓練集和驗證集分開。

操作：

1. 按「AI 更新」。
2. 切換到「模型更新」。
3. 設定自動標註最低信心；預設 `0.90`。
4. 設定 epochs；預設 `100`。
5. 按「開始離線更新」。

資料分流：

- x 高信心，且 x 與 s 類別、數量、位置一致：加入自動候選集。
- x 與 s 不一致：進入人工確認區。
- 低信心或 unknown：保留供人工標註。
- 同一工單／批次不會同時分散到訓練集和驗證集。

訓練完成後：

- 新 s 模型會自動註冊並啟用。
- 舊模型不會被覆蓋。
- 可在「模型版本與回復」選擇舊版本，再按「使用／回復到選取版本」。

注意：移機後若資料庫中的模型路徑仍指向舊電腦，回復操作會顯示模型檔不存在；這是第 1 節提到的絕對路徑問題。

## 9. 生產資料保存位置

所有 Python 生產資料預設位於：

```text
code/production_data/
```

主要內容：

| 路徑 | 內容 | 是否建議備份 |
|---|---|---|
| `peanut_production.sqlite3` | 工單、逐顆花生、異常、訓練樣本索引、模型版本 | 必須 |
| `peanut_images/<工單>/` | 每顆花生通過中央時的裁切圖，保留部分背景 | 建議 |
| `training_captures/<工單>/images/` | 無框線與文字的完整原始幀 | 要保留訓練資料時必須 |
| `training_captures/<工單>/metadata/` | 當幀全部花生的類別、信心值、Track ID 與座標 | 要保留訓練資料時必須 |
| `training/` | 自動標註、train/val 資料集、訓練輸出與新模型 | 要保留模型歷史時必須 |
| `weight_calibration.json` | 面積換算重量的校正公式 | 校正後必須 |

`peanut_production.sqlite3` 是 SQLite 資料庫，不是一般文字檔。程式會自動讀寫，不需要另外啟動 SQLite。若要人工查看表格，可使用 SQLite 圖形化檢視工具；查看前先備份，避免誤改正式資料。

### 備份方式

1. 按「停止」。
2. 關閉 GUI。
3. 複製整個 `production_data` 到備份磁碟或另一個資料夾。
4. 備份資料夾名稱建議加入日期，例如 `production_data_backup_20260830`。

不要只備份 SQLite 而漏掉圖片與訓練資料；資料庫內的紀錄會指向這些檔案。

## 10. 重量校正

設定檔：

```text
code/production_data/weight_calibration.json
```

目前預設：

```json
{
  "enabled": false,
  "formula": "linear",
  "coefficient_a": 0.0,
  "coefficient_b": 0.0,
  "exponent": 1.0,
  "note": "待加入實測面積與重量校正資料"
}
```

`enabled` 為 `false` 時：

- 每顆重量不會被估算。
- 累計重量顯示「待校正」。
- 不會因目標重量而停止。

不要在沒有實測公式時自行改成 `true`。後續取得花生面積與實際重量關係後，再填入係數。

線性公式：

```text
重量(g) = coefficient_a × 七幀平均面積(px²) + coefficient_b
```

冪次公式：

```text
重量(g) = coefficient_a × 面積^exponent + coefficient_b
```

## 11. 常見問題

### 找不到模型

確認：

```text
花生機/yolo/yolov26s_best.pt
花生機/yolo/yolov26x_best.pt
```

注意 `yolo` 必須與 `code` 同層，不是在 `code` 裡面。

### 找不到影片

按 GUI 的「選擇影片」，重新選擇新電腦上的影片檔。

### `python` 不是內部或外部命令

重新安裝 Python 並勾選加入 PATH，或改用 `py -3.11`。若 `.venv` 已建立，可直接使用：

```powershell
.\.venv\Scripts\python.exe .\run_gui.py
```

### 缺少模組，例如 `No module named ultralytics`

```powershell
.\.venv\Scripts\python.exe -m pip install -r .\requirements.txt
```

### 辨識很慢

先檢查 PyTorch 是否使用 GPU：

```powershell
.\.venv\Scripts\python.exe -c "import torch; print(torch.cuda.is_available())"
```

若顯示 `False`，目前使用 CPU。也請確認 NVIDIA 驅動與 PyTorch 安裝版本相容。

### GoPro／攝影機無法開啟

- 關閉其他正在占用攝影機的程式。
- 確認 Windows 相機隱私權允許桌面應用程式存取相機。
- 將攝影機索引由 `0` 改為 `1` 或 `2`。
- 確認 GoPro 已進入可供 Windows 使用的 webcam 模式。

### Qwen 分析顯示 timed out

- 第一次載入 9B 模型可能較慢。
- 確認 Ollama 在背景執行。
- 執行 `ollama ps` 查看模型狀態。
- 關閉其他大量占用 GPU／記憶體的程式後再試。
- 程式等待上限已設為 300 秒；統計功能本身不需 Qwen，可先按「計算統計」。

### 清除「已達生產數量」後又立刻停止

這是目前預期行為。舊工單的累計重量仍然已達標，因此重新開始會再次觸發異常。需要繼續另一批生產時，應建立新工單。

### 為什麼看到花生通過中央後沒有立刻增加數量

程式要收集中央後 3 幀，才能完成中央前後共 7 幀的平均判定，因此最後結果會有短暫延遲。
